Guía de uso

Cómo crear un componente, una variante o una versión nueva, y cambiar su estado, con la IA (Claude Code) y las skills del proyecto. Las skills generan solo la estructura: los estilos, el marcado y la lógica los escribe el maquetador.

Cómo pedírselo a la IA

Una skill es un conjunto de instrucciones guardado en .claude/skills/<nombre>/SKILL.md. Claude Code la carga cuando la tarea coincide y sigue sus pasos: qué preguntar, qué script ejecutar y qué no tocar. Así todos los componentes salen con la misma estructura.

2. En lenguaje natural

Pídelo como se lo pedirías a un compañero; la IA reconoce la skill que corresponde.

Crea una nueva versión del componente button

Buenas prácticas

  • Da todo en un solo mensaje (componente, título, descripción). Lo que falte, la IA lo pregunta junto, también en un solo mensaje.
  • Usa el nombre visible de la referencia (Excel / Figma): Icons + Border, Dropdown / Select. El id y el slug se calculan solos (icons-border).
  • La descripción es una línea y puede quedar vacía; se cambia luego en la cabecera del HTML.
  • No pidas CSS ni marcado al crear: la base se entrega solo como plantilla y la variante aparece como Preview pending hasta que escribas el ejemplo.
  • Revisa el resultado con npm start (http://localhost:4321); las carpetas nuevas aparecen solas en el menú.

Crear un componente

/crear-componente

Crea un componente int-* nuevo con toda su estructura de documentación, listo para maquetar. Úsala cuando el componente todavía no existe en el menú.

Qué te pregunta

  1. Título del componente (Chip). El id se deriva en kebab-case (chip).
  2. Descripción del componente (una línea, opcional).
  3. Descripción de la variante Basic (opcional).
  4. Diseñador a cargo (Yony León, Gabriela Javier o Christian Abanto).

Al final pregunta "¿Deseas crear otra variante?" y, si dices que sí, sigue con /crear-variante.

Cómo pedirlo

/crear-componente
Crea el componente Chip. Descripción: "Chips represent entities using icons, labels and images."
Crea el componente Tag y después las variantes Severity y Rounded

Qué genera

src/components/chip/
├── chip.config.ts          id del componente (+ orden u ocultar variantes)
├── routes.ts               ruta /components/chip
├── chip-page.ts            página de documentación
└── version-1/
    ├── base/
    │   ├── chip.ts         <int-chip> con solo status = 'pending' y designer
    │   └── chip.html       cabecera con título y descripción
    ├── variants/basic/     siempre: example.ts + example.html (Preview pending)
    └── styles/
        ├── _index.scss     punto de entrada (@use)
        └── _chip.scss      plantilla TOKENS · BLOCK · ELEMENTS · MODIFIERS · SKELETON, sin CSS

También lo registra una vez en src/components/inventory.ts (posición en el menú). Es el único registro manual: variantes y versiones se detectan solas.

Crear una variante

/crear-variante

Agrega un ejemplo (una sección de la documentación) a un componente que ya existe. Cada variante es una carpeta variants/<slug>/: aparece en el menú y en la página sin registrarla en ningún lado.

Qué te pregunta

  1. Componente: id o nombre visible (accordion, Dropdown / Select).
  2. Título de la variante (Icons + Border, Raised).
  3. Descripción (una línea, opcional).

Se crea en la versión más reciente, salvo que pidas otra.

Cómo pedirlo

/crear-variante accordion Icons + Border
Agrega la variante Raised a button: "Raised buttons display a shadow to indicate elevation."
Nuevo ejemplo Disabled de input en la versión 1

Qué genera

src/components/accordion/version-N/variants/icons-border/
├── example.ts      AccordionIconsBorderExample: importa solo la base
└── example.html    solo la cabecera (title + description); debajo escribes el ejemplo

Enlace directo: /components/accordion#accordion-icons-border. El título y la descripción se editan en la cabecera de example.html, nunca en un .ts.

Crear una versión

/crear-version

Abre version-N+1/ como copia exacta de la última versión (base, variantes y estilos) para cambiar la implementación sin romper la publicada. La versión anterior no se toca y la página muestra un desplegable de versiones.

Qué te pregunta

  1. Componente: te indica cuál es la última versión y cuál va a crear.
  2. Título en la versión nueva (por defecto, el mismo).
  3. Descripción en la versión nueva (conviene contar qué cambia).

Al final pregunta si quieres crear otra variante en la versión nueva.

Cómo pedirlo

/crear-version button
Crea la versión 2 de tabs con la descripción "Header with icon and badge."
Versiona demo, mismo título y descripción

Qué genera

src/components/button/
├── version-1/      intacta, sigue publicada
└── version-2/      copia de version-1: base/, variants/ y styles/
                    base/button.ts → comentario "version 2" y status = 'pending'
                    base/button.html → cabecera actualizada

Cada versión es enlazable con /components/button?version=1; por defecto se abre la más reciente. No confundir con una variante visual (V1 / V2 de Tabs en el Excel), que es un modificador .int-tabs--v2 dentro de la misma versión.

Cambiar el estado

/cambiar-estado

Cada versión de un componente tiene un estado que la página muestra como chip, junto a la versión. Así cualquiera sabe si el componente ya se puede usar. Avísale a la IA cuando empieces a maquetar y cuando termines.

Estado Chip Cuándo
pending Recién creado (componente o versión nueva): solo la estructura. Es el valor por defecto.
in-progress Lo estás maquetando.
done Terminado y listo para usar.

Qué te pregunta

  1. Componente: id o nombre visible.
  2. Estado: puedes decirlo con tus palabras (terminado, listo, en progreso, pendiente).
  3. Versión: por defecto la más reciente; solo pregunta si hablas de una anterior.

Cómo pedirlo

/cambiar-estado button in-progress
Ya terminé el accordion, márcalo como done
La versión 1 de tabs está lista
¿Qué componentes están pendientes?
El tooltip ahora lo ve Gabi

Qué cambia

src/components/button/version-1/base/button.ts

export class IntButton {
  /** Implementation status, shown on the documentation page: pending → in-progress → done. */
  static readonly status: 'pending' | 'in-progress' | 'done' = 'in-progress';
  /** Designer in charge of this version, shown on the documentation page and in Reference → Status. */
  static readonly designer = 'Yony León';
  …
}

Es la primera línea de la clase, así que también puedes cambiarla a mano: el editor te ofrece los tres valores. Es por versión: version-1 puede estar Done mientras version-2 sigue In progress. Una versión nueva empieza en Pending. Debajo va designer, el diseñador a cargo: el avance de cada uno se ve en Status.

Resumen rápido

Si prefieres no usar la IA, cada skill tiene un script de npm equivalente (salvo crear el componente).

Quiero… Skill Script
Un componente nuevo /crear-componente —
Un ejemplo en un componente existente /crear-variante npm run new:variant -- <id> "<Título>" --description "…"
Cambiar la implementación sin romper la actual /crear-version npm run new:version -- <id> [--title "…"] [--description "…"]
Cambiar título o descripción Editar la cabecera del HTML (base/<id>.html o example.html)
Cambiar el estado (pending · in-progress · done) /cambiar-estado npm run set:status -- <id> <estado> [--version <N>]
Verificar npm start · npm run build · npm test
